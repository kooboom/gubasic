# 입력기 기록 페이지

[English](README.md)

실제 입력기가 Flutter 입력 칸에 보내는 것을 기록합니다: 모든 값(글자, 아직 조합 중인 부분, 선택 범위), 키, 포커스 변화, 클릭. 기록은 테스트 입력입니다: `packages/gubasic_runtime/test/text_box_test.dart`가 `test/ime_logs/`의 모든 파일을 재생합니다(DESIGN 9.1절).

지금까지의 기록: `windows-chrome.json`(Windows 한글 입력기, Chrome), `macos-chrome.json`(macOS 한글 입력기 두벌식, Chrome).

## 기록하는 방법

먼저 고정된 Flutter인지 확인하고(`packages/gubasic_runtime`에서 `dart tool/check_flutter.dart`), 다음을 실행합니다.

```sh
cd packages/gubasic_runtime/tool/ime_probe
flutter pub get
flutter run -d chrome --release
```

1. 시스템 입력기를 한글(두벌식)로 바꿉니다.
2. 페이지의 다섯 시나리오를 차례로 합니다. 시나리오마다 칠 키가 적혀 있습니다. 테스트는 시나리오마다 마지막 **다시** 뒤의 기록만 씁니다. 4번 시나리오는 일부러 "다시"를 한 번 누릅니다(버튼 A, 그다음 버튼 B).

   > **새로 시도할 때마다 먼저 "다시"를 누릅니다.** 잘못 친 것을 손으로 지우면 그 과정이 기록에 남고, 테스트가 검사하는 내용에 섞입니다. 첫 Windows 기록에는 이런 시도가 두 번 섞여 있습니다.

3. 오른쪽 위 **저장 (Save)**을 누릅니다. 맥에서는 `ime-log-macos-chrome.json`, Windows에서는 `ime-log-windows-chrome.json`이 내려받아집니다.
4. `ime-log-` 접두어를 빼고 테스트 폴더에 복사합니다.

   ```sh
   cp ~/Downloads/ime-log-macos-chrome.json ../../test/ime_logs/macos-chrome.json
   ```

5. `packages/gubasic_runtime`에서 `flutter test`를 실행합니다. 새 파일은 자기 테스트 그룹을 따로 받고, 두 층으로 검사합니다.
   - **LANGUAGE 11.1절의 규칙**은 모든 기록에 똑같이 적용합니다. `Text`에는 확정된 글자만 있고, `Changed`는 확정될 때마다 한 번 실행되며, 치는 중인 음절은 나오지 않고, 마지막 `Text`가 같아야 합니다. 이 중 하나가 실패하면 런타임이 이 입력기에서 약속을 지키지 못하는 것입니다. 테스트가 아니라 런타임을 고칩니다.
   - **이 기록이 만든 이벤트 순서 그대로**는 `test/text_box_test.dart` 끝의 `recorded`에 고정합니다. 새 기록은 여기서 자기가 만든 이벤트를 보여 주며 실패합니다. 직접 친 내용과 맞는지 눈으로 확인한 다음 추가합니다. 이 층은 입력기마다 다를 수 있습니다. 다만 Windows와 macOS 기록은 같은 이벤트를 만들었습니다. 나중에 여기서 실패하면 Flutter를 올리면서 그 입력기의 동작이 바뀐 것입니다.

   기록은 모두 남겨 두고, 손으로 고치지 않습니다.

## 기록에서 본 것

지금까지의 기록에서 본 동작과, 그것을 보여 주는 시나리오입니다. 두 기록은 모든 시나리오에서 같은 이벤트를 만들었습니다. 다른 것은 도중의 신호뿐입니다(아래 스페이스 항목).

- **조합 중 백스페이스는 입력기 안에서 풀립니다.** 한은 하가 되고(시나리오 3), 값은 갑, 가, ㄱ이 되고(5-1), 긂은 글, 그, ㄱ이 됩니다(5-2). 조합 중인 글자가 자모 하나씩 줄어들 뿐 아무것도 확정되지 않고, `Changed`도 실행되지 않습니다. Windows와 macOS.
- **확정된 음절은 한 번에 지워지고, `Changed`가 한 번 실행됩니다.** 조합이 다 풀린 뒤의 백스페이스는 닭(5-1)이나 한(5-2)을 통째로 지우며, 달이나 하로 바꾸지 않습니다. `Changed`는 짧아진 글자로 한 번 실행됩니다. Windows와 macOS.
- **조합 중이기만 했던 글자는 `Changed`에 나오지 않습니다.** 5-2의 긂과 5-1에서 지우는 동안의 값은 확정된 적이 없으므로 `Changed`에 나타나지 않습니다. 5-2에서 `Changed`는 한과 빈 칸일 때만 실행됩니다. Windows와 macOS.
- **스페이스는 앞 음절과 함께 확정됩니다.** 닭 다음에 `Changed`는 `닭 `은 보지만 `닭`만 따로는 보지 않습니다(시나리오 2). 신호는 다릅니다. macOS는 스페이스를 먼저 조합 안에 넣고(`닭 `을 조합 중), Windows는 조합 중인 닭을 확정된 `닭 `으로 한 번에 바꿉니다. Windows와 macOS.
- **입력 칸을 떠나면 확정됩니다.** 두 입력기 모두 입력 칸이 포커스를 잃을 때 조합 중인 글자를 확정합니다. 웹에서는 클릭이 도착하기 150~180 ms쯤 전입니다(시나리오 4).
