# 알려진 문제

[English](KNOWN_ISSUES.md)

알고 있지만 지금은 **일부러** 고치지 않은 문제를 적어 둡니다. 항목마다 무엇인지, 왜 미뤘는지, 언제 다시 볼지를 적습니다. 문제를 고치면 같은 변경에서 항목을 지웁니다.

---

## 아주 긴 반복이 느림

- **무엇:** 100만 번 도는 반복(`total = total + i * 2 - 1`)이 놀이터의 웹 최적화 빌드에서 약 3초, VM에서 약 0.8초 걸립니다.
- **왜 미뤘나:** 정확성 문제가 아니고, 초보자가 쓰는 프로그램 규모에서는 체감되지 않습니다.
- **다시 볼 때:** 놀이터나 IDE에서 실제로 느리다는 사례가 생길 때, 또는 트랜스파일러 단계.

## 설정 기능을 아직 쓸 수 없음

- **무엇:** `SaveSetting`과 `GetSetting`은 실행 전에 진단하며(A029) 쓸 수 없습니다.
- **왜 미뤘나:** 설정을 저장하는 곳이 플랫폼마다 다릅니다(앱은 shared_preferences, 놀이터는 브라우저 저장소). 인터프리터와 생성된 앱이 같은 방식으로 저장하도록 `gubasic_runtime`과 함께 만들어야 합니다(D11).
- **다시 볼 때:** `gubasic_runtime`이 생길 때.

## 폼이 있는 프로그램은 아직 실행할 수 없음

- **무엇:** 코드는 폼 파일과 함께 검사합니다(D27). 컨트롤, `Me`, 이벤트 처리기를 알고, README 예제([examples/hello](../examples/hello))에는 진단이 없습니다. 하지만 폼이 있는 프로그램을 실행하는 곳은 아직 없습니다. 인터프리터가 이벤트를 전달하지 않고, 폼을 보여 주는 것도 없습니다. 놀이터에는 폼이 없으므로 거기서는 여전히 컨트롤과 `Me`를 알립니다(A003).
- **왜 미뤘나:** 폼을 실행하려면 인터프리터의 이벤트 처리와, 컨트롤을 보여 줄 `gubasic_runtime`이 필요합니다. 각각 다음 변경에서 하나씩 들어옵니다. 놀이터에서 HTML로 컨트롤을 흉내 내면 두 번째 런타임이 생기므로 하지 않습니다(D24).
- **다시 볼 때:** IDE의 실행 창이 생길 때.
